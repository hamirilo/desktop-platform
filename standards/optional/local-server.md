# Optional Standard: ローカル受付（127.0.0.1 の HTTP）

**適用条件**：ツールが 127.0.0.1 で HTTP を待ち受ける。ブラウザ拡張からの保存、MCP サーバー、ほかのアプリやスクリプトからの操作が該当する。

待ち受けは「このパソコンの中の、許可した相手だけ」に閉じる。Web ページからの接続は常に拒否する。

## 1. 待ち受け

- `127.0.0.1` だけで listen する。`0.0.0.0` にしない。
- ポートは固定し、README に書く（stockroom は拡張が 41620、MCP が 41621）。隣のポートを別の用途に使う。開発用の headless サーバーは別のポート（+10）にして、アプリの代わりに答えないようにする。
- 待ち受けるのは **アプリが動いていて、設定でオンにしている間だけ**。既定はオフ。
- 用途が違う受付（取り込みだけ / 整理だけ）はサーバーも token も分け、片方だけオンにできるようにする。

## 2. 認証

- すべてのリクエストに `Authorization: Bearer <token>` を要求する。token はアプリが生成し、アプリの設定にだけ置く。
- `Host` が `127.0.0.1` / `localhost` 以外なら拒否する（DNS リバインディング対策）。
- `Origin`：ブラウザ拡張向けは拡張の origin だけを許す。MCP など拡張以外向けは `Origin` が付いていたら拒否する（MCP クライアントは付けない。付くのは Web ページ）。
- 設定画面に「token を作り直す」と「すべての接続を解除」を置く。

## 3. ペアリング

アプリが書き出した拡張以外（別の PC から持ってきたもの、開発中のもの）が接続するときの手順。

- 相手が `POST /pair?code=NNNN` で 4 桁の番号を送り、アプリが **同じ番号をダイアログに出して** ユーザーに許可を求める。両方に同じ番号が出ていれば同じ要求だと分かる。
- 許可されたときだけ token を返す。拒否された相手は一定時間（30 秒）再要求できない。要求のたびにアプリが前に出るので、繰り返させない。
- ペアリングの質問は同時に 1 つだけ。

## 4. 受け付けるもの

- body の上限を決める（300 MB など）。同時に読む body は 1 つにする。
- ファイルは相手（拡張）がブラウザの Cookie とプロキシ設定で取ってきて bytes を送る。アプリは URL を取りに行かない。
- 受け取ったファイルは [Security](../security.md) §4 のとおり外から来たものとして扱う。

## 5. 外から来る変更

- データに書き込むのは **アプリだけ**。別プロセスから DB ファイルを直接開かせない（同時書き込みと UI の更新漏れを避ける）。
- AI（MCP）に出す操作は読み取り、タグ、フォルダ、表示名、メモまで。**削除、ゴミ箱、取り込み、書き出しは出さない。**
- 外から来た変更はまとめ単位で記録し、アプリから元に戻せるようにする（[Architecture](../architecture.md) §7）。

## 6. 実装の形

- 待ち受けと停止は 1 つのモジュール（`loopback.rs`）に寄せ、用途ごとのサーバーがそれを使う。
- JSON-RPC や MCP の最小実装は `tiny_http` の上に自前で書く。tokio / axum を入れない（[Rust Recommendations](../../recommendations/rust.md)）。
- アプリ（Tauri の `AppHandle`）への依存は trait（`Host`）で挟み、テストと headless の example から Tauri なしで動かせるようにする。
- MCP を Claude Desktop から使う場合は、同じバイナリに `--mcp` の stdio 中継モードを持たせ、動いているアプリへ転送する。
